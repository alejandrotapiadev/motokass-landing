Cómo subir un producto a la tienda y venderlo

Todo lo necesario para dar de alta un casco, guantes, chaqueta, camiseta o botas en la tienda online de MOTOKASS, con sus fotos, colores, tallas y stock, y qué hacer cuando un cliente lo compra. Relacionado: herramientas.html · arquitectura.html.

⏱ 10–15 min por producto🛠 Supabase (panel web)💻 Sin tocar código

Un solo Supabase para todo. La preview de develop y la web en producción leen la misma base de datos. Cualquier producto que marques como activo aparecerá en todas las versiones de la web que tengan la tienda.

Hoy la tienda solo existe en develop (rediseño V2). En www.motokass.com no se verá nada hasta que el rediseño pase a main.

Los productos DEMO desaparecen solos. En las previews se muestran productos [DEMO] mientras la tabla esté vacía. En cuanto subas el primer producto real, los DEMO dejan de mostrarse.

Preparar Supabase

Crear las tablas de la tienda y un espacio para las fotos. Si ya está hecho, salta al paso 1.

Ya hecho el 28/09/2026. Tablas equipment_products y equipment_variants creadas (con RLS) y bucket público productos creado (solo imágenes JPG/PNG/WebP/AVIF, máx. 5 MB). Puedes ir directamente al paso 1. Estas instrucciones quedan como referencia.

0.1 · Crear las tablas

  1. Abre el SQL Editor de Supabase.
  2. Copia todo el contenido del archivo supabase/migrations/20260928_equipment.sql del proyecto.
  3. Pégalo en el editor y pulsa Run.
  4. En el Table Editor deben aparecer equipment_products y equipment_variants.

0.2 · Crear el espacio para fotos

  1. En Supabase, menú lateral → Storage → New bucket.
  2. Nombre: productos. Activa Public bucket (las fotos tienen que verse en la web).
  3. Pulsa Save.

En el bucket productos guarda solo fotos de producto: al ser público, cualquiera con el enlace puede verlas.

1
Cada producto

Reunir los datos del producto

Ten a mano esta información antes de empezar. Todo debe ser real: nada de precios, reseñas o características inventadas.

Categorías y tipos válidos

Escribe los valores exactamente así (minúsculas, sin tildes). Si no coinciden, el producto no aparece o no se puede filtrar.

cascosintegral · modular · jet · off-road · trial · adventure
guantesverano · invierno · off-road · urbano · impermeable
chaquetastextil · cuero · verano · invierno · adventure · urbana
camisetasmanga-corta · manga-larga · tecnica
botastouring · racing · off-road · adventure

Tallas recomendadas: ropa y cascos XS S M L XL XXL 3XL; botas 38 a 47. Se ordenan solas en la web si usas estos valores.

2
Cada producto

Preparar y subir las fotos

Las fotos son lo más importante para vender. La primera es la principal y la segunda aparece al pasar el ratón por la tarjeta.

✔ Formato recomendado

Cuadradas (1:1), mínimo 1200×1200 px, fondo blanco o transparente, JPG/WebP de menos de 300 KB.

✔ Qué fotos

1ª: producto de frente. 2ª: lateral o detalle. Opcional: una foto por color.

✔ Nombres de archivo

Sin espacios ni tildes: casco-marca-modelo-negro-1.jpg

✘ Evitar

Fotos con marca de agua de otras tiendas, capturas de pantalla o fotos con derechos de terceros.

  1. Supabase → Storage → bucket productos.
  2. Crea una carpeta por categoría (p. ej. cascos) y sube las fotos.
  3. Haz clic en cada foto → Get URL / Copy URL. Tendrá esta forma:
https://qjddrchpwljecavsryrg.supabase.co/storage/v1/object/public/productos/cascos/casco-marca-modelo-negro-1.jpg

Guarda las URLs: las pegarás en el paso siguiente.

Formato del campo colors

Un JSON con un objeto por color. El name tiene que ser idéntico al que pongas luego en las variantes. images es opcional: fotos específicas de ese color.

[
  { "name": "Negro mate", "hex": "#1a1a1a" },
  { "name": "Blanco", "hex": "#f2f2f2", "images": ["https://…/casco-blanco-1.jpg"] }
]

Al guardar, copia el valor de la columna id del producto (un código largo tipo 3f2c…). Lo necesitas en el paso 4.

Alternativa: crear el producto con SQL (más rápido si tienes práctica)

En el SQL Editor, sustituye los valores de ejemplo y ejecuta. Devuelve el id del producto creado.

-- Sustituye TODOS los valores de ejemplo por los reales
insert into equipment_products
  (slug, brand, name, category, type, price, compare_at_price, description,
   images, colors, features, materials, tags, badges, featured, active)
values
  ('casco-marca-modelo', 'Marca', 'Casco integral Modelo X', 'cascos', 'integral',
   129.90, null,
   'Descripción real del producto.',
   array['https://…/foto-1.jpg', 'https://…/foto-2.jpg'],
   '[{"name":"Negro mate","hex":"#1a1a1a"},{"name":"Blanco","hex":"#f2f2f2"}]'::jsonb,
   array['Característica real 1'], array['Material real'], array['negro','blanco'],
   array['new'], false, true)
returning id;

Cada producto

Crear las variantes (color × talla) con su stock

Cada combinación que vendes es una fila en equipment_variants. Ejemplo: 2 colores × 4 tallas = 8 filas.

CampoQué ponerEjemplo
product_idobligatorioEl id copiado en el paso 33f2c…
skuobligatorioReferencia única de la variante (aparece en el pedido)MODX-NEG-M
colorsi hay coloresIgual que el name de colorsNegro mate
sizesi hay tallasTallaM
stockobligatorioUnidades disponibles de esa combinación3
eanopcionalCódigo de barras—
priceopcionalSolo si esta talla cuesta distinto. Vacío = precio del producto.—

Con SQL es mucho más rápido cuando hay muchas tallas:

-- Sustituye el id del producto, los SKU, colores, tallas y stock reales
insert into equipment_variants (product_id, sku, color, size, stock) values
  ('ID-DEL-PRODUCTO', 'MODX-NEG-S',  'Negro mate', 'S',  2),
  ('ID-DEL-PRODUCTO', 'MODX-NEG-M',  'Negro mate', 'M',  3),
  ('ID-DEL-PRODUCTO', 'MODX-NEG-L',  'Negro mate', 'L',  1),
  ('ID-DEL-PRODUCTO', 'MODX-BLA-M',  'Blanco',     'M',  0);

Cómo se muestra el stock

En stock: 4 o más en total · Últimas unidades: 1–3 · Sin stock: 0. Las tallas con 0 aparecen tachadas.

Producto sin tallas ni colores

(Una camiseta de talla única, un accesorio…) No crees variantes: rellena el campo stock del propio producto.

Comprobar el producto en la web

La web refresca los datos cada minuto. Espera 1 minuto y abre la ficha.

https://develop.motokass.com/equipamiento/CATEGORIA/SLUG
# Ejemplo:  https://develop.motokass.com/equipamiento/cascos/casco-marca-modelo

No hay que tocar nada más: el producto se añade solo al buscador, al sitemap de Google, a "Productos relacionados" y, si tiene rebaja, a la sección de Ofertas.

Cada pedido

Vender: qué pasa cuando un cliente compra

Hoy la web no cobra online. El cliente prepara su carrito y lo envía por WhatsApp; la venta se cierra con él directamente.

1. Clienteelige color, talla y cantidad → "Añadir al carrito"
→
2. Carritopulsa "Continuar con la compra"
→
3. WhatsAppllega un mensaje al 653 97 32 09 con productos, variantes, SKU y subtotal
→
4. Túconfirmas disponibilidad en tienda
→
5. Túacuerdas pago y entrega con el cliente
→
6. Túactualizas el stock en Supabase
Lo hace la webLo haces tú

Ejemplo de mensaje que recibirás

Hola MOTOKASS, quiero hacer este pedido:

• 1 × Marca Casco integral Modelo X (Negro mate, talla M) [MODX-NEG-M] — 129,90 €

Subtotal: 129,90 €
¿Me confirmáis disponibilidad y cómo completar la compra?

Después de cada venta: descontar el stock

  1. Supabase → Table Editor → equipment_variants.
  2. Busca la fila por el SKU que viene en el mensaje (p. ej. MODX-NEG-M).
  3. Resta las unidades vendidas en stock y guarda. En 1 minuto la web lo refleja.
-- Alternativa SQL: restar 1 unidad a un SKU
update equipment_variants set stock = stock - 1 where sku = 'MODX-NEG-M' and stock > 0;

Si vendes en la tienda física una unidad que también está online, descuéntala igual. Si no, la web seguirá ofreciéndola.

Precios del carrito: antes de cobrar, comprueba que el precio del mensaje coincide con el actual. El carrito guarda el precio del momento en que el cliente añadió el producto.

¿Cuándo se podrá cobrar online con tarjeta?
Cuando se integre una pasarela de pago (Stripe, Redsys…). Antes hay que definir y publicar: condiciones de venta, derecho de desistimiento (14 días), política de envíos y devoluciones, y los métodos de pago. Hasta entonces la web no muestra "pago seguro", "envío gratis" ni "devoluciones", porque no están configurados.

Solución de problemas

El producto no aparece en la web
  • Espera 1 minuto: la web refresca los datos cada 60 segundos.
  • Comprueba que active = true.
  • Comprueba que category es exactamente cascos, guantes, chaquetas, camisetas o botas.
  • Recuerda: hoy la tienda solo está en develop, no en www.motokass.com.
La ficha da error 404
La URL tiene que ser /equipamiento/<category>/<slug> con los valores exactos del producto. Revisa mayúsculas, tildes o espacios en el slug.
Sale "Sin stock" aunque tengo unidades
El stock se suma desde equipment_variants. Revisa que las variantes tengan el product_id correcto y stock mayor que 0. Si el producto no tiene variantes, usa el campo stock del producto.
Al elegir un color todas las tallas salen agotadas
El color de las variantes no coincide exactamente con el name del campo colors (mayúsculas, espacios, tildes). Deben ser idénticos.
No se ven las fotos
El bucket productos tiene que ser público y la URL debe contener /object/public/. Abre la URL en el navegador para comprobarla.
Error "duplicate key" al guardar
Ya existe un producto con ese slug o una variante con ese sku. Ambos deben ser únicos.
Siguen saliendo productos [DEMO]
Solo salen en las previews cuando no hay ningún producto real activo. En cuanto haya uno, desaparecen. En producción nunca se muestran.
